3. Как будет работать

Принцип: снимаем у полки быстро, разбираем потом сидя. У полки книга занимает ~5 секунд, медленная часть (поиск, выбор издания, ручной ввод) отложена и не тормозит остальные.

У полки — телефон (PWA)

  • 📷 есть штрихкод ISBN → скан → в очередь;
  • 🖼️ штрихкода нет → фото титульного листа → в очередь (текст распознаётся потом на сервере);
  • ⌨️ запасной путь — два-три слова названия + год;
  • к каждой записи сразу пишется полка;
  • 📴 офлайн-очередь: без сети снимки копятся в телефоне и уходят при появлении связи;
  • книга уже в каталоге (узнаётся по ISBN) → «уже есть», записывается только полка.

В фоне — сервер

  • распознавание фото титула (Tesseract, русский язык) → название, автор, издательство, год;
  • поиск по цепочке источников: РГБ и FantLab (кто первый — решается на этапе 2 по замеру; РГБ 7 из 8, FantLab 3 из 8) → alib.ru для того, чего нет в обоих. Open Library на русских книгах — 0 из 7, из цепочки убрана; Google Books не проверен;
  • вежливый темп: пауза между запросами, кэш ответов. 5000 книг ≈ 1,5 часа фоном;
  • штрихкод не 978/979 (магазинная наклейка) → отклоняется, по нему не ищем;
  • старая орфография при поиске приводится к современной (ѣ→е, і→и, ѳ→ф, конечный ъ).

Разбор очереди — компьютер

✅ однозначное совпадениеподтверждение пачкой
⚠️ несколько изданийвыбор по году и издательству
❌ не нашлосьручная карточка, когда будет настроение

Вслепую ничего не сохраняется: российские издательства, по имеющимся сведениям, повторно используют ISBN — подтверждение обязательно.

5. Стек — на обсуждение

Части, не зависящие от выбора: SQLite как база, PWA как приложение на телефоне (камера, офлайн, без магазина), Tesseract для фото, HTTPS обязателен (камера в браузере без него не работает) — приём sslip.io + Let's Encrypt уже отработан на «Сиделках».

ВариантЗаПротив
A. Python + SQLite, фронт на чистом JS рекомендуюкак «Сиделки» — проверенный путь развёртывания; лучшие библиотеки для обработки фото перед распознаванием (выровнять, высветлить пожелтевшую бумагу); быстро писать разбор ответов каталоговразвёртывание — интерпретатор + зависимости, а не один файл
B. Go + SQLiteодин бинарь, мало памяти — удобно на сервере в 1 ГБ; Go в контуре уже естьобработка изображений и разбор HTML беднее; OCR всё равно внешний Tesseract
C. Нативное Android-приложение (Tauri 2 / Kotlin)полный контроль камеры и фокусавторой код; не нужен, пока PWA справляется. Запасной путь, не стартовый

Почему A рекомендовался: самое неизвестное место проекта — распознавание старых титулов, и там важнее всего обработка изображения.

Решено 22.10.2026: Go (вариант B). Один бинарь с автозапуском на домашней машине; SQLite без CGO; фронт PWA на чистом JS, встроенный в бинарь. Обработку фото перед распознаванием проверить на этапе 0 — на чистом Go или внешним инструментом рядом с Tesseract; выбор по результату на настоящих титулах.

7. Риски

  • ⚠️ Распознавание старых титулов — бледная печать, жёлтая бумага. Не проверено. Если плохо — набор текста, и время у полки растёт с ~7–8 до ~20+ часов (оценка, не замер).
  • ✅ Нон-фикшн — FantLab про художественную литературу, но РГБ нашла и учебник, и советские издания без ISBN (проба 29.10.2026, 7 из 8).
  • ⚠️ РГБ — правила автоматических запросов к search.rsl.ru не найдены. До ответа — только редкие запросы по одной книге, с кэшем; массовый прогон не делать.
  • ✅ LiveLib — импорт снят с плана (08.11.2026), риск больше не касается работы.
  • ⚠️ Повтор ISBN у российских издательств — лечится обязательным подтверждением.
  • ⚠️ HTTPS дома — камера в Chrome требует защищённого соединения, а Let's Encrypt через sslip.io не выдаст сертификат на адрес домашней сети. Варианты: флаг Chrome «считать этот адрес защищённым» (для разработки), свой сертификат, установленный в телефон, или Tailscale с его HTTPS. Ни один ещё не проверен на телефоне.
  • ⚠️ Машина выключена — телефону некуда отправлять; спасает офлайн-очередь (снимки ждут в телефоне). Вне дома без туннеля сервер недоступен.
  • ⚠️ Оценка ценности — автоматической не будет: цена книги зависит от состояния, тиража и спроса, а каталоги цен не знают. Система подсказывает аналоги, сумму ставит человек; оценка без даты и основания в базу не пишется.
  • ❌ alib.ru блокирует частые запросы — формального соглашения не нашёл, но сайт выдаёт «Заблокировано за слишком частое обращение», а на форуме продавцы пишут, что за робота блокируют IP. Массовая ночная оценка всех 5000 книг отменяется: оценка — по запросу и для кандидатов, с кэшем и редкими запросами (решение 22.10.2026, замена прежнего «автоматически для всех»).
  • ⚠️ Сдвоенные тома и мусор в полях — FantLab знает «Том 6-7» одной книгой и пишет в поле ISBN «отсутствует» (и «отсутсвует»).
  • ⚠️ Число томов в собрании — откуда брать «всего томов». Кандидат — FantLab (у изданий есть серии), не проверено; запасной путь — ввести вручную один раз на собрание.
  • ✅ Место под фото — ~1,5 ГБ на 5000 книг; на домашней машине не проблема. Нужна резервная копия базы и фото.

8. Открытые вопросы

  1. HTTPS для телефона: флаг Chrome, свой сертификат или Tailscale? Нужен ли доступ вне дома?
  2. LiveLib: разрешение на выгрузку полок после проверки правил. Снят: импорт убран из плана 08.11.2026.
  3. Ценность: для себя (решено). Оценивать все 5000 или только кандидатов — отмеченных вами и найденных по признакам редкости? Рекомендую второе.
  4. Для разведки: 10 ISBN с полок и 5–10 фото советских титулов.
  5. РГБ: можно ли обращаться к search.rsl.ru программой (редко, с паузами, с кэшем) — правил не нашёл; спросить РГБ или найти Z39.50/SRU-доступ, адрес которого тоже не нашёлся.
